# 古さ判定のテストケース

実装済み・テスト済み: 1〜13、16〜19（`test/staleness.test.ts`）、H1〜H7（`test/hook.test.ts`）。14、15 はスキーマ読み取りの段階で作る。

一時的な git リポジトリを作り、履歴を再現して期待値を決める。実装より先に、このケースをテストにする。

S = 画面の Markdown（`login.md`）、C = 「コード」が指す実装ファイル（`a.ts`）。

| # | 履歴 | 期待 |
|---|------|------|
| 1 | C と S を同じコミットで追加 | 揃っている |
| 2 | S と C を追加。その後 C だけ変更 | 実装の方が新しい |
| 3 | 2 のあと S を変更 | 揃っている |
| 4 | C を main で変更、S を C の変更を知らない枝で変更し、マージ | 実装の方が新しい（S は C の変更を知らずに書かれた） |
| 4b | C を main で変更、その main を取り込んだ枝で S を変更し、マージ | 揃っている |
| 5 | C と S を同じコミットで変更し、その後 rebase / squash | 揃っている |
| 6 | C が複数。片方だけ S より新しい | 実装の方が新しい（新しいファイルを出す） |
| 7 | S が、無関係な画面の C2 の変更の後に変更された | C には影響しない |
| 8 | C を改名（`git mv`）。S は旧パスのまま | 旧パスはエラー（パスが無い）。新パスでは、改名のコミットが変更として数えられ、実装の方が新しい |
| 9 | C を削除 | エラー（パスが無い） |
| 10 | C が未追跡の新規ファイル | 比べない（コミットされるまで） |
| 11 | C に未コミットの変更があり、S は無変更 | 作業中の差分あり |
| 11b | C と S の両方に未コミットの変更 | 揃っている（S は書かれている最中） |
| 11c | S が新規で未コミット | 揃っている |
| 12 | 時計がずれたコミット（日時が逆順） | 日時ではなく祖先関係で決める |
| 13 | 同じ C を複数画面が載せる。C だけ変更 | 載せている全画面が「実装の方が新しい」 |
| 18 | コードの行が repo の外を指す（`../x`、絶対パス） | エラー（パスが無い） |
| 19 | コードの行が git のパス指定の記法（`:(glob)*.ts`）や `-` で始まる名前 | 文字どおりのファイル名として扱う |
| 14 | 「データ」のテーブルがスキーマに無い | エラー |
| 15 | スキーマが無い | テーブル名の一覧のみ、図は空。エラーにしない |
| 16 | リポジトリが git 管理でない | 古さは出さず、参照の実在だけ検査する |
| 17 | 浅い clone（履歴が途中まで） | 判定できないと出し、「揃っている」とは出さない |

## フック

| # | 状況 | 期待 |
|---|------|------|
| H1 | 見出しが欠けている | 止める |
| H2 | 行が長すぎる | 止める |
| H3 | コードの行にパスが無い | 止める |
| H4 | C を載せている画面の S が一つも変わっていない | 止める |
| H5 | C を載せている画面のうち一つの S が変わった | 通す |
| H6 | どの画面にも載っていない実装ファイルだけが変わった | 止めない（「未登録」と出す） |
| H7 | どの画面にも載っていないファイル（README など）だけが変わった | 止めない |

## 決まっていないこと

- 行の長さの上限: 仮に 80 文字（サンプルの最長行は 54 文字）。実際のエージェントの出力を見て決め直す
- 画面の置き場と実装のパターンの既定値（今は仮に `docs/screens/**/*.md`、`src/**` と `app/**`）
- 17 の浅い clone で、CI にどう伝えるか
